# Constitución de vpmadrid

vpmadrid es una app para contar los puntos de un partido de voley.

## Principios fundamentales

### I. Simplicidad ante todo

- Si hay dos soluciones posibles, se elige siempre la más simple.
- Esto es una versión 1: nada de complejidad "por si acaso" ni preparada para el futuro.
- Cualquier complejidad extra debe justificarse por escrito en el plan.

**Por qué**: una app sencilla se entiende, se prueba y se cambia con facilidad.

### II. Español de España

- Todo lo que ve el usuario (textos, botones, mensajes, errores) está en español de España.
- La documentación del producto (spec, plan, tareas) también está en español de España.

**Por qué**: es el idioma de quienes van a usar la app.

### III. Cero alcance fantasma

- NO se implementa ninguna funcionalidad que no esté escrita en la spec.
- Si surge una idea nueva, se propone (para añadirla a la spec), no se construye.

**Por qué**: así lo construido coincide siempre con lo acordado, y nada aparece sin que
alguien lo haya decidido.

### IV. Verificable por una persona no técnica

- Cada criterio de éxito debe poder comprobarse usando la app, sin leer código.
- Un criterio que solo pueda comprobarse mirando el código no es válido y debe reescribirse.

**Por qué**: cualquier persona puede confirmar que la app hace lo que promete.

## Gobernanza

- Esta constitución está por encima de cualquier otra práctica del proyecto.
- Cada spec, plan y lista de tareas debe respetar estos cuatro principios. Si algo los
  incumple, se corrige o se justifica por escrito.
- Para cambiar la constitución: se propone el cambio, se aprueba y se actualiza la versión.
  - MAYOR: se elimina o redefine un principio.
  - MENOR: se añade un principio o se amplía uno de forma importante.
  - PARCHE: aclaraciones o cambios de redacción.
